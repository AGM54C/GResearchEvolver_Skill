# 22 篇论文：方法、证据、局限与实现决策

## P01 — Actionable Hallucination Detection

- **问题与机制**（pp.3–4）：研究的是工具参数是否得到用户上下文支持，不是一般科学事实真假。冻结基础模型，LoRA 并行处理工具调用，在 `[POS]` 后输出错误类型及具体参数；损失只监督诊断部分。
- **实验**（pp.8–9）：具体参数反馈相对笼统阻断提高恢复率；ID 轨迹成功率 16.4%→22.1%，但 OOD 仍约 2%。不能把参数 F1 提升写成普遍任务成功。
- **局限**（p.10）：模拟用户、单名人工标注者；需要 hidden states，严重分布偏移削弱信号。没有权限/日期信息时，猜一个“合理值”也不构成授权。
- **落地**：工具输入记录每个关键参数的来源；缺少必要参数时返回字段级问题。提供诊断插件契约，默认使用可审计的结构检查，不宣称实现或训练了 Latent Critic。

## P02 — Auditing Failure Attribution

- **机制**（pp.3–4）：限制输入、移动线索、剩余样本准确率、改变聚合权重四种审计。能预测标签不等于评判模型真的利用了该线索。
- **证据**（pp.4、6–8）：ALFAgent 单步分类器 311/311；仅判断 reasoning 结束位置达 310/311。AFTraj 的相同总体分数掩盖注入/自然失败的相反强弱；把所有 agent 都判错能获得相近 micro-F1，但 exact-set 很差。
- **局限**（p.9）：来源和领域存在混杂；对零样本模型的线索移动结果不能外推所有评估器；替代合法归因可能被标签判错。
- **落地**：归因/评审评测同时保存自然与注入来源、简单基线、precision/recall/exact-set、分层结果与不确定性；不把多数票、总分或单一标签当因果真值。

## P03 — Automated Hypothesis Validation / POPPER

- **机制**（pp.3–4、13）：主零假设必须蕴含每个子零假设；每轮 e-value 在过去信息条件下期望≤1，乘积成为 e-process，越过 1/α 才拒绝零假设。p→e 校准不修复无效 p 值或数据窥探。
- **证据**（pp.6–8）：在生物靶点及 DiscoveryBench 中评估功效和一类错误；不同骨干不都满足名义错误控制。人工研究只有 9 人。相关性检验不自动证明机制。
- **局限**（pp.15–16）：单个假设的一类错误控制不等于多假设 FDR，也不等于发现为真；错误主要包括 p 值误读、无效检验与蕴含关系破坏。
- **落地**：设计冻结、分析单位/数据分割、竞争解释、失败尝试日志、固定样本统计与多重校正。序贯模块要求明确条件有效性及数据使用记录；条件不足时拒绝输出“有错误率保证”的结论。接受负结果。

## P04 — DeFA

- **机制**（pp.3–5）：协议依赖与语义依赖形成事件图；候选错误召回后构建传播图；分段保留本段全文及其他段摘要，再作归因。协议边可由确定性程序提取，语义边仍是推断。
- **证据**（pp.6–9）：Who&When 精确步骤定位最高 52.7%；去掉传播边而保持候选集合，降至 40.2%。长轨迹 33–130 步仍仅 17.2%。技能演化下游是电子表格任务。
- **局限**（p.9）：关系识别会错；日志中的反事实判断未实际运行就不能称因果验证；下游泛化尚未证明。
- **落地**：区分程序观察到的依赖和推断依赖；保留原始事件 ID、使用关系与证据；定位产生修复假设，经分支执行验证后才沉淀经验。

## P05 — DiLLS

- **机制**（pp.5–7）：activity→action→operation 三级组织，串起目标、计划修订、步骤状态及原始日志。摘要提供导航，原始操作记录用于确认。
- **证据**（pp.10–13）：12 人、4 个 GAIA 案例的平衡设计；平均发现失败 2.25→3.67，并改善自评信心/负荷。
- **局限**（p.13）：主要验证诊断，未让用户执行修复验证；发现更多问题不等于所有问题都正确，信心不是正确率；技术实现依赖集中式编排。
- **落地**：控制台分运行/阶段/事件三层，显示未执行和阻塞原因；摘要不得伪装成隐藏思维链或真实因果机制；模型建议可被人修改或驳回。

## P06 — DISCOVERYWORLD

- **机制**（pp.3–6）：8 主题×3 难度×5 种子，共 120 个模拟科学发现任务；仪器观测、实验、假设更新形成闭环。另设基础操作任务以区分工具能力与科学能力。
- **证据**（pp.6、9）：分开计算任务成功、过程进展、解释性知识；人类可能靠穷举成功而不获得机制解释，agent 完成操作也未必发现规律。
- **局限**：人为构建的虚拟世界及已知机制不等于真实开放科学，知识评分部分依赖模型。
- **落地**：端到端示例分开报告执行完成、证据支持、解释与反证；模拟测试明确标为模拟。通用接口允许接入真实领域环境，不内置“正确科学答案”。

## P07 — Does RL Really Incentivize Reasoning Beyond the Base Model?

- **机制**（pp.2–5）：用 pass@k 观察有限采样下可解题覆盖，区分 pass@1 的采样效率与广度；手查数学推理以排除猜中答案。
- **证据**（pp.10–12）：所研究 RLVR 配置中，小 k 提升可以伴随大 k 覆盖下降。作者明确未充分覆盖更大训练计算与所有大模型。
- **局限**：有限 k 的零成功不是绝对不可能；不同训练设置、蒸馏起点、预算不可混为一谈。
- **落地**：RSI 同时看平均质量、任务覆盖/失败族覆盖和成本，保留多种候选策略；不将文本策略改写等同于权重训练，也不宣称能力边界必然扩大。

## P08 — DoVer

- **机制**（pp.4–7）：按重新规划分 trial；提出归因、生成干预、固定前缀后重跑。区分规划错误与执行能力不足。实际干预是否被遵循是独立变量。
- **证据**（pp.7、10–11）：每项三次运行；原文 Validated 使用 2/3 成功，部分验证使用里程碑改善；存在大量 Inconclusive，工具缺失无法只靠文本解决。
- **局限**：依赖状态保存；主要改消息；进展和遵循度包含模型评估。一次翻转仍可能来自随机性，不是唯一根因证明。
- **落地**：修复前缀快照、配对未改动对照、重复运行、遵循检查；没有有效执行或环境漂移时标 inconclusive。进展按任务里程碑，不能按完成 skill 数代替。

## P09 — InconLens

- **机制**（pp.3–6）：以语义信息节点对齐多次运行，不按相同第几步硬对齐；模型建议节点，开发者可合并/拆分/重命名并确认依赖。
- **证据与局限**（pp.9–10）：用户反馈支持较低认知负担，但节点提取及状态评估仍可幻觉；高度分岔的开放任务未必有统一节点集合。
- **落地**：人工可编辑的里程碑与跨分支对照，保留不同路径和未对齐项；默认以稳定 stage/milestone ID 对齐，语义匹配只作建议。确定性结构差异与模型语义差异分开呈现。

## P10 — Interactive Debugging and Steering / AGDebugger

- **机制**（pp.5–8）：暂停、单步、修改消息、恢复 agent 状态、fork 新会话；每次消息前 checkpoint。需要 save_state/load_state，而非仅删后文。
- **证据**（pp.8、11–12）：诊断和干预是两项小样本研究；两项 GAIA 任务、短时实验。
- **局限**（pp.7、11–12）：good-enough 状态不等于精确恢复；邮件等外部动作不可撤回；干预可能不被遵循或只是随机好运。
- **落地**：运行目录/配置/产物版本化，暂停在可说明的执行边界生效，取消终止受管进程；fork 保留父运行。外部状态恢复质量及不可逆动作单独标明。

## P11 — One Reflection Is Not Enough / SAGE

- **机制**（pp.5–7、20–21）：无指标执行故障先修复；结构性失败产生 3–5 个原因，独立 critic 评审，固定 router 决定局部/方法/设计修复；数据充分性限制随意抛弃负结果；数值注册表约束报告。
- **证据**（pp.8、11–13）：12 主题上恢复 11 个；相对优势集中在代码与执行，结果分析仍弱；6 个 ML 主题有人类评审。消融是有限任务及评判设置。
- **局限**（pp.7、12、21）：数值 sanitizer 不证明方法真的执行；表格删掉未测数字后，正文仍可能声称它存在；阈值敏感性只重放决策，没有重跑实验。
- **落地改进**：诊断候选必须证据定位；负结果受保护；数值绑定“指标+条件+单位+run”，同时审计正文和表格，禁止只匹配一个任意出现的数字。

## P12 — ProRL

- **机制**（pp.3–4）：长程 GRPO/DAPO、KL 正则及参考策略/优化器重置，保持探索，起点为蒸馏后的 1.5B 模型。
- **证据**（pp.6–9）：任务分为广度下降、平台、持续改善三类；部分新任务和更难图问题有广度收益，并非所有任务一致提高。
- **局限**（p.15）：高计算需求、只验证一类模型规模、重置复杂性和有限任务覆盖。
- **与 P07 对读**：二者训练起点、任务、计算与方法不同，不能从表面相反标题选一个绝对结论。
- **落地**：监测策略多样性、预算和停滞；允许预算内分支探索，回归覆盖不可只看单个最佳分数。论文训练算法不是本 skill 的默认训练实现。

## P13 — ReCast

- **机制**（pp.3–6）：冻结 LLM 的多层 hidden states，选归因相关层；成功轨迹均值作偏离参照；双分支投影、双向编码器、root/non-root 对比与列表排序损失。
- **证据**（pp.7、9）：四类归因基准，多随机种子，消融支持若干组件；预计算特征后的效率不包含全部 hidden-state 提取成本。
- **局限**：监督标签与单个最早根因目标约束了适用性；高 hidden-state 相似度不是因果证据，闭源 API 无法直接复刻。
- **落地**：标准化步骤/候选列表/成功对照接口，为白盒插件保留特征引用；默认不下载模型或伪造隐状态，最终仍以可执行干预验证。

## P14 — RSI Survey: Bounded Refinement to Autonomous Loops

- **框架**（pp.3–4、17–20）：区分改输出、改训练、改评估器、改研究过程；验证信号层次与 loop closure 分开。验证层次是定性总结而非已测定律。
- **关键警示**（pp.19–20、28–29）：自我确认、分布/多样性坍缩、目标锁定；把问题做对与选对问题是不同要求。留存失败既能帮助也可能锁住方向。
- **局限**：arXiv 收集和定向补检塑造样本比例，不能视为全领域的无偏比例或开放 RSI 已成立的证据。
- **落地**：将经验、候选、已晋升策略分开；开放目标修订入口，保存修订理由与继续适用的约束；元优化器本身需单独评估，不能默认随候选晋升。

## P15 — Recursive Self-improvement of AI Research Agents / AIDE2

- **机制**（pp.3–5）：内循环改任务代码，外循环改 agent harness；公开训练反馈与私有选择评分分离，固定每任务预算，真实运行候选后比较。
- **证据**（pp.6–10、24）：8 天、99 个改写提案、7 次接受；独立任务族与跨模型测试支持部分迁移。不同检查点在不同基准非单调。
- **限制**（pp.10–13、26）：ignition test 三种子不足以说明更好的 agent 是更好的自改进器；有些看似合理的评分惩罚不改变排序；被拒策略约四分之一公开分数提高、私有分数未提高。
- **落地**：候选/现任必须执行同一任务、相同种子和预算；保留拒绝记录；任务级配对区间、保护性指标、独立迁移测试；搜索预算与部署收益分开。

## P16 — SCIRIGOR

- **机制**（pp.3–4、13）：D→T→R→C 的执行证据链；独立数值 oracle、数据视图与分析单位匹配，语义 judge 不能覆盖结构或数值失败。原文另有视觉支撑，本次绘图范围不纳入。
- **证据**（pp.8–10）：高执行率和结果→文本自洽共存于低目标忠实度；最强 strict 成功 18%；多数首次断裂在数据/变换或执行契约。
- **局限**（p.9）：观察到的首个坏边不是隐藏规划/认知原因；候选自述 provenance 只提供待验证关系。
- **落地**：保存输入哈希、命令、环境、输出、统计与论断；分别报告结构可追溯、数值复算、语义支持，不以“JSON 合法”冒充科学验证。

## P17 — Self-Authored Verification / SEAL

- **机制**（pp.3–4）：自写测试仅反馈；不可观察的外源 audit 用同种子比较候选/现任，反馈一位 accept/reject，拒绝时保留整个 policy+tests 状态；最终 deployment 测试不用于接受。
- **证据**（pp.5–7）：Atari 中高自评分与低真实表现共存；等提案数试验表明收益部分来自保留已获得能力。
- **局限**（p.7）：audit 是有限样本代理，论文展示 audit 提升而 deployment 降低；非退化接受不等于严格改善，不能承诺单调提升。
- **落地改进**：固定评价契约、全状态回滚、选择/晋升审计/最终报告分开；本地同权限隔离只标 process-only，不标 sealed。严格改善与防退化是两个不同门控。

## P18 — Red Queen Gödel Machine

- **机制**（pp.3–5、19）：epoch 内评估器固定；候选评估器由独立 ground-truth anchor 评估；更换时仅使依赖旧评估器的统计失效，保留原始产物，按需重新评分。
- **证据**（pp.6–9）：代码、写作/评审、证明/评分及奖励设计；写作接受率是自动评审面板分数，不是期刊接受率。角色效用和 epoch 分数不能不加条件跨期比较。
- **局限**（p.39）：模型服务更新破坏 epoch 平稳性；anchor 会有噪声和偏见；生成文稿及证明未统一经人类专家评估。
- **落地**：探索性 reviewer 可以改进，发布门控保持独立；评估器变更创建新 epoch、失效受影响分数但不抹历史。晋升 reviewer 需标注校准数据和误报/漏报，不能奖励“一律拒绝”。

## P19 — Tracing the Cascade / SCHEMA

- **机制**（pp.3–7）：小样本干预诊断与大规模论断审计是两个模块；概念图分类型合并，单独报告未加权与拓扑加权严重度，图外论断仍有基线权重。
- **证据**（pp.3–4）：141 失败轨迹修复 65；错误频率、结构位置、可修复性不能混为一个维度。
- **限制与本项目不同选择**（pp.6、15）：首个非空检索层短路可能遗漏反证；去掉 hedge 会损害科学范围。度数仅作排查优先级，不等于事实错误或实际因果影响。
- **落地**：保留原措辞、否定、量词和 scope；检索反证与独立来源；传播影响标“潜在受影响”直至重算/复核，未知≠错误。

## P20 — TruthInsightBench

- **机制**（pp.8–10、24–26）：40 个跨领域计算任务；6 维 29 项，覆盖证据、稳健性、对照、独立泛化、新颖性、可证伪性。计划做的检验不算做过。
- **证据**（pp.12、14）：同一冻结基础模型、单次运行的四种框架总分近似；配对统计不支持明确冠军。独立泛化接近零同时涉及数据不可行、agent 纪律和单阶段任务限制。
- **局限**（p.19）：单模型单运行、dry-lab、单冻结 judge，专家校准待做。
- **落地改进**：逐项记录 done/not-done/not-applicable 和理由，分离发现与验证；保留空结果与反例；不以不适用项默认满分，也不按论文权重宣称普适科学质量。

## P21 — Who&When Pro

- **机制**（pp.4–6）：成功轨迹中注入一种错误，warm-start 保持前缀；静态工具缓存、动态环境检查漂移；之后重跑并筛选失败，形成 agent/step/mode 标签。
- **证据**（pp.5–6）：12,326 轨迹；100 条人工抽样，多数认同并非全库无噪声。定位步骤与识别错误类别有不同困难。
- **局限**（p.19）及 P02 对读：单决定性错误、合成来源和模板线索限制泛化，联合准确率与多原因归因应分开。
- **落地**：测试含自然失败、多个同时错误、无错误和格式扰动；原始前缀校验失败则不作可比较干预；不生成虚假的唯一根因标签。

## P22 — XAgen

- **机制**（pp.4、10–11）：日志结构化、组件级人工反馈、版本化配置、独立异步 judge，支持历史重放；judgment 是 yes/no/unsure。
- **证据**（p.5）：8 人的短时、主观体验为主的初步研究；人工反馈功能参与度偏低。
- **局限**（p.5）：当时以线性工作流为主，客观正确率/时间和组件消融仍待验证；temperature=0 不保证确定性。
- **落地**：反馈定位到阶段/证据/论断；支持 DAG、迭代新阶段和可追踪配置修改。unknown 保留为 unknown，不静默按 0.5 当作半个事实。

## 综合设计判断

1. 原 skill 的 RSI 实际主要是反思与知识沉淀。新版把候选执行、固定评估、统计比较、晋升与回滚落实为程序。
2. HCI 应是随时查看、修正、暂停、恢复和分支对照的能力；不是每次下载/可逆编辑都审批。
3. Evidence-based 至少有三种不同验证：来源确实存在且定位正确、实验实际执行并可复算、论断在范围与强度上被支持。三者分别报告。
4. 不照抄论文阈值作为通用真理；阈值需冻结、可解释且可校准。多 persona 不保证独立；多次自评不等于外源真值。
5. 系统能保存和检查证据，不因此自动创造科学真值。领域判断、数据访问、不可逆外部行为与研究目标仍允许人介入。
