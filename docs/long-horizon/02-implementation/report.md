# 长程科研 Agent：实现报告

## 为什么与实现了什么

在完整 Agent 上增加可持久化的长程研究协调，不删除任何既有技能或科研操作。MemTX 以源代码形式随本地项目保存，不需要安装外部同名包；科研条目仍是节点，关系仍是 typed edges，OpenViking 继续作为可选检索／同步投影。

## 具体实现

| 模块 | 行为 |
|---|---|
| `vendor/memtx/` | 固定上游提交、9 个原样文件、逐文件 SHA-256/Git blob 清单；启动 worker 先核验 |
| `memtx.py` / `memtx_worker.py` | JSON 子进程边界，避免上游通用模块名污染宿主；CAS 快照恢复、乐观版本和单项目写锁；调用原事务方法；不执行 mock 工具 |
| `validity.py` | 科研依赖、版本和条件检查；显式替代支持组合；通过上游 MemTX 级联撤回，保留旧产物和失效原因 |
| `long_horizon.py` | 项目目标／约束、研究条目、实际决定、共享预算、动作绑定、科学审阅、上下文归档、真实工作流观察与项目报告 |
| `agent.py` | 执行前与 worker 内再次检查前提；预算预留和意图原子提交；回执、报告索引、预算原子结算；自动交接，续接保留项目身份与人工反馈 |
| `agent_tools.py` / `cli.py` | 6 个新增原生工具、8 个项目／MemTX JSON 操作和 `long-watch` 命令；人工操作不能由模型填写 actor 冒充 |
| 工作台 | 创建／关联项目、显示条目与累计预算、按条目记录决定、登记执行既有工作流、观察真实结果、分页查看历史上下文 |
| 完整性／备份 | 核验归档链、项目与 MemTX 快照引用；备份包含项目报告和所有 CAS；doctor 列出未结算预留及待完成任务 |
| 受控 RSI | 新模块进入原能力目录；改进提案可引用具体项目快照、条目哈希、实际 outcome 和证据；保留原审批／采用门槛 |

上游冲突规则是有限规则系统：同来源的等权新值可以替代旧值，不同来源的等权冲突会要求审查。适配层不将自报置信度或 `action_safe` 状态称为科研正确性；科学条件与真实人工审阅单独执行。

## 使用方式

工作台的“跨会话长期研究”先创建项目，再将会话关联到其 ID。命令行例子与完整字段见 [长程运行手册](../../../skills/_shared/long-horizon-guide.md)。

每个科学阶段继续产生版本化 `report.md`，长期项目另生成 `<store>/projects/<project>/report.md`。项目级人工决定会进入相关会话的真实反馈，并撤回未执行的旧动作；已发生的外部副作用仍须核查。

图更新后需要重新绑定科学动作。受影响节点变为 `needs_review`，显式其他支持仍成立的节点保留，但记录支持变化及范围审查要求。原材料不删除，修复后用新版本图和 fresh MemTX memory_id 重新校验。

## 人工介入与边界

研究者控制总体方向、条目／分支选择、条件解释、实际实验预算和策略采用。本地 CLI／控制台是可信人类入口，通用 `run_command` 仍是经明确审阅的本机命令，不构成抵抗恶意同权限代码的安全沙箱。

MemTX 的 compensation 是日志中的补偿决定，没有执行远程撤销。预算覆盖受管模型／工具进程；任意命令里自行调用的收费 API 或第三方账单不能自动准确计量，应通过登记工作流和明确成本控制。项目活动时间采用受管 worker 的执行时间，等待实验和重试退避不是模型工作时间。跨主机高可用、长期压力测试和科学效益仍未由本轮证明。
