# Agent 重型化：设计取舍

## 为什么做

原系统有 26 个科研技能和 82 个 CLI 科研操作，但模型接口只有文本生成，缺少原生工具续接与跨模型调用的持久会话。人需要手动把目标、技能、工具、文件和反馈串起来。用户要求保留全部功能，演示可以聚焦，产品不能裁掉能力。

## 实现什么

新增完整能力 Agent，而原有技能、显式 DAG、统计/证据模块、科研图谱/OpenViking、RSI、绘图、PPT 及宿主工作流保留。渐进读取技能说明用于控制上下文，不作为删除功能的理由。标准库即可启动工作台；特定科研依赖和模型按需使用。

## 怎么做

Responses/Chat/Ollama 原生工具协议 → 持久会话控制器 → 有类型工具网关 → 原有研究运行器/科研操作。模型和工具均使用现有独立进程监督器；先记意图、再执行、核对结果、事务提交。完整能力分成常规自动操作、精确受审阅操作、保留给人的裁决/采用入口。

每个科学阶段要求可追溯 report.md 和浅显解释。对话进行中研究者可提交新方向并撤回未执行旧计划。RSI 允许引用 Agent 报告与实际反馈作为改进提案来源，采用仍须冻结验收和真人决定。

## 局限与取舍

本轮不无依据加入后训练、多智能体协商或付费服务。先使真实工具链、错误恢复和人机交互可运行，再用失败数据判断训练需求。预算限制的是请求数、输出预留、上下文与活动时间，不是货币账单。工具命令在可信本机执行，不等于权限隔离。

## 研究者审阅

建议后续体验时重点观察：默认“关键取舍介入”的停顿是否合适；报告解释能否支持实际研究判断；哪些高频已审阅命令值得配置更细粒度的固定执行策略。本阶段未伪造已收到的使用反馈。
