## 真实模型的失败与改进

两轮使用同一研究任务、请求模型及 8 次模型请求、12 次工具调用、300 秒活动时间、16000 输出预留 token 的上限。

| 观察 | 初版 | 加入接口查询与预算提示后 |
|---|---|---|
| 状态 | 预算耗尽；计算成功但没有报告/产物 | 完成交付 |
| 模型请求 | 8 | 7 |
| 工具调用 | 8，其中 1 次参数超限失败 | 6，全部成功 |
| 提供方报告输入 / 输出 token | 83907 / 309 | 67693 / 1832 |
| 受管活动时间（当时版本口径） | 47.43 秒 | 95.46 秒 |

初版花费过多轮次查阅接口说明。随后增加单操作字段查询、字符分页约束和每轮剩余预算提示，复测完成计算、写文件和报告。保留 [初次失败](live-agent-initial.json)、[完整示例产物](live-result-example.md) 和 [阶段报告](live-stage-report.md)。仅一个开发期任务的前后观察，不能据此估计总体成功率或科学能力增益；完成更多工作也花了更多时间。

原始请求、响应、监督日志与 SQLite/CAS 保留在开发工作区 `GResearchEvolver-Agent-Validation-20261021/live-model*/state/`；分发源码包包含不带凭据的摘要和示例产物。真实调用对应源码哈希在各自回执中；之后补充的备份、完整性与安装范围检查由最终离线回归验证，不将早期线上调用冒充为所有最终路径的线上实测。

## 交付检查

源码根目录 `build_agent.py` 生成包含全部技能、运行器、文档、例子和测试的项目包，附每文件哈希。自动测试已验证同一份源码重复构建得到相同 ZIP、26 个技能全在、原始内容和 ZIP 均小于 200 MB；最终分发文件的精确大小与 SHA-256 在 ZIP 旁的 `.manifest.json` / `.sha256` 中。

这是 Agent 项目包。比赛要求的视频、PPT、码道证明等需要真实补齐；本轮 Codex 开发没有被记成码道开发。

## 未由这些检查证明的事项

没有跨领域能力增益结论、用户研究结论或工业服务等级结论。公开服务的认证、租户隔离和高可用仍需独立实现。已批准远程请求的副作用不能靠终止本地进程自动撤销。
