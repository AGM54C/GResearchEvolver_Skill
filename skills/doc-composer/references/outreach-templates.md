# 四形态输出模板

> 被 `doc-composer` Phase 1 引用。骨架与红线，不是死板填空——受众参数可微调措辞深度。

## 1. xiaohongshu（300-800 字）

```
[钩子标题 ≤20 字：真实收益点，不虚构]
[首段：身份/场景切入，2-3 句，真实体会]
[分点 3-6 个：emoji 节制（≤3 种），每点 = 干货 + 一句个人体验]
[收尾：真实局限或适用条件（可信度来源）]
[话题标签 3-6 个：品类大词 + 场景词 + 长尾词]
```

红线特检：标题钩子可情绪化但不得断言源内容外的事（「方法救命」可、「发了 3 篇顶会」无据不可）；数字保留精度或用「约」；未决用「我目前的观察是」。

## 2. blog（1500-4000 字）

```
# 标题（问题式或主张式）
引言：为什么写这篇（真实动机/踩坑）
背景：读者需要的最少前置
主体：过程/方法/结果（分节，代码块/图引用）
局限：如实列出
参考：文献/工具链接（真实 URL）
```

红线：结论强度对齐源；代码可运行（复制即用）；参考链接真实可访。

## 3. report（结构化全量）

```
摘要（150 字：做了什么/发现什么/建议什么）
背景与目标
分主题发现（每发现带证据引用：claim_id/数据表/文献）
结论与建议（区分「数据支撑」与「判断」）
附录：数据表/方法细节
```

红线：发现-证据一一对应；建议区分事实推断与价值判断。

## 4. weekly（200-500 字）

```
本周完成：3-5 条，数据化（跑了 X 个 run/读了 Y 篇）
关键发现：1-2 条（带证据指针）
问题与卡点：如实（阻塞项标阻塞原因）
下周计划：3 条内，可验证的目标式
```

红线：完成项与 runs/trace 可对账；不虚报进行时。

## 通用纪律

- 断言登记表先建后写（Phase 0），形态重排不改内容只改包装；
- 四形态共用同一底账——同源不同形态间数字必须一致（小红书版与 report 版的同一数字不得不同）。
