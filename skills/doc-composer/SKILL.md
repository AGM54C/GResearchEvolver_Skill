# doc-composer Skill

研究产物的传播形态转换。**核心纪律：传播力不得以真实性为代价——钩子（标题/情绪/标签）只能包裹真实内容；夸大数字、抹掉未决限定、把初步结果写成定论，都是本 skill 的红线违规。**

> **验收标准**：按 `references/composer-qa-rubric.md` 打分；C2（真实性）= 0 → 作废。
>
> **诚实边界**：本 skill 产「可直接发布的稿」，最终发布由人执行（不自动发任何平台）。

---

## 1. 工作流

### Phase 0：内容源解析 + 断言登记

- 读 source，提取全部可传播断言，逐条登记：数值（精度）/ 结论强度（已验证/初步/未决）/ 证据指针（claim_id/run 号/文献条目）；
- **断言登记表是后续一切形态的单一事实源**——形态重排不改内容，只改包装。

### Phase 1：形态模板重排

四形态模板要点（详见 `references/outreach-templates.md`）：

| 形态 | 结构骨架 | 长度 |
|---|---|---|
| xiaohongshu | 钩子标题（≤20 字）+ 首图文案建议 + 3-6 个分点（emoji 节制使用）+ 真实体会收尾 + 话题标签（3-6 个） | 300-800 字 |
| blog | 引言（为什么写）→ 方法/过程 → 结果 → 局限 → 参考（链接化） | 1500-4000 字 |
| report | 摘要 → 背景 → 分主题发现（带证据引用）→ 结论与建议 → 附录（数据表） | 结构化全量 |
| weekly | 本周完成（数据化）→ 关键进展/发现 → 问题与卡点 → 下周计划 | 200-500 字 |

### Phase 2：真实性校验（形态后）

- 逐断言比对登记表：数值精度未升格（55.94% 不得变「近 60%」**当语境是精确报告**；概略表述时用「约」标示）、结论强度未升格（「初步表明」不得变「证明」）、未决项要么保留限定要么不写；
- **小红书形态特检**：情绪钩子 vs 内容真实性分离审查（标题可以抓眼球，但不得断言源内容没支撑的事——「读文献救命技巧」可以，「用这个方法发了 3 篇顶会」没有就是编造）。

### Phase 3：交付

- 稿件 + 断言登记表（对账底账）+ 发布建议（最佳形态细节：首图文案/标签选择理由/发布时间建议——建议非指令）。

## 2. 产物

```
out_dir/
├── <form>-draft.md        ← 可发布稿
├── claims-ledger.md       ← 断言登记表（源断言 → 形态呈现 → 强度核对）
└── publish-advice.md      ← 发布建议（非指令）
```

---

## 3. Gate Check

- 断言登记表覆盖稿内全部可验证断言
- 数值精度与结论强度零升格（逐条核对记录留存）
- 未决项处理合规（保留限定或不写）
- 钩子不虚构源内容外的声称
- 无自动发布动作（发布由人执行）

## 6. 运行机制（遵守 HARNESS.md）

- **工具调用**：纯文本加工，无外部调用（源读取除外）。
- **错误恢复**：E6 幂等（同 source + 同 form + 同 audience → 同稿）。
- **人的介入**：H1（形态/受众歧义）；发布动作永远留给用户（H2 精神：不做不可逆的外部动作）。
- **Agent Memory**：M2 产物存 `workspace/composer/`；sidecar 刷新。
- **轨迹与归档**：断言核对记录入 trace；产物入 artifacts。
