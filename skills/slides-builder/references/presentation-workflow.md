# 科研叙事、模板和视觉检查

## 按受众和场景组织

- 组会：目前问题、证据/负结果、卡点、备选、希望得到的意见和下一步。
- 论文报告：作者的问题与方法、关键原图/表、条件与局限、自己的理解和与当前课题的关系。
- 答辩：问题价值、贡献和证据链、方法选择、验证、限制与可据证回答的备份页。
- 会议/spotlight：按实际时间缩小论证范围，保留关键证据和边界，不按固定页数压缩所有内容。
- 教学：直观例子→形式化→具体应用→适用边界→理解问题。

storyboard 每页关联来源和讲稿时长；“先讲结论”不等于把假设写成确定事实。若学术判断仍有分歧，展示分歧和下一步区分实验。

## 模板和编辑

先查看实际模板的主题、尺寸、母版、页/对象/图片/图表/讲稿清单和渲染图。原文件保持不变。文本替换应精确定位对象与原文，保留格式；替换后重新检查换行。清理残余姓名、旧数据、单位标志和空占位，但未经要求不移除有意义的来源。

基础 deck_tools 的 edit 只修改指定文本 run，未变更 ZIP 部件保留原字节。它不复制幻灯片、不编辑图表数据、不重建动画。复杂模板应使用 Office/LibreOffice 或另写经过测试的 OOXML 操作，检查关系、图表工作簿、notes、media 和打开/渲染结果。原生图表数据的变化必须重新绑定数据来源。

## PPTX、Beamer、Marp

PPTX 使用可编辑文本/形状；简单定量图优先原生图表。复杂区间/专用图可以嵌入从来源数据生成的高质量图，同时交付可编辑绘图源，不把它说成原生 PowerPoint 图表。精确公式可使用 OMML 或 Beamer；SVG/PNG 公式应附 LaTeX 源并注明其编辑方式。

Beamer 使用宿主已安装编译器，显式 `--no-shell-escape`；中文选择支持的引擎和已安装字体。保存 `.tex`、`.bib`、素材、版本和编译日志。不得因编译缺包而静默改写公式。

Marp 输出 Markdown 与主题；页面、notes、数学和图像逐项验证。导出 PDF/HTML/PPTX 的工具行为可能不同，不能用 Markdown 语法通过替代实际导出检查。

## 三种检查分开记录

1. **内容**：来源、数字、限定、公式、页序、讲稿、引用和备份页；研究者是否认可故事主线。
2. **文件**：PPTX 部件/关系、图表工作簿、尺寸、对象边界、资源是否保留，源文件/输出哈希。
3. **视觉**：由实际渲染器导出的每一页；检查文本裁切、换行、字形、覆盖、图像比例、公式和投影可读性。

PowerPoint 和 LibreOffice 渲染可能不同，记录实际引擎和版本。没有引擎时仍可交付待审草稿，但必须把视觉检查列为未完成。修正后再次渲染当前文件；过期预览不能用于当前版本的接受。

需要记录逐项结果时使用 [演示审阅记录](slides-qa-rubric.md)。

## 从反馈改进

将意见绑定 slide id/shape id/claim id/report id，区分纠错、受众需求和个人审美。更改主张/取舍回到研究者，局部排版修复在约定预算内执行。AI 提出和比较候选，研究者控制采用；没有真实用户观测时不宣称理解、说服力或科研 taste 提升。
