# diagnosis-clinician Skill

科研推理的两层诊断 + 证据资格裁决。**本 skill 是唯一汇聚点**：输入来自 literature（论断图）、experiment（复现结果）、survey/idea（推断）的产物，也是最严格的证据裁决者。

> **核心原则（P0）**：证据资格的裁决**不依赖图连通**——图路径连通 ≠ 因果/支持（HypoKG/G-Retriever 边界）。裁决走规则层（Stored-Is-Not-Supported 的来源角色/有效期/权限）。
>
> **验收标准**：报告按 `references/diagnosis-qa-rubric.md` 打分；D1（依据可追溯）或 D2（规则层裁决）= 0 → 作废重做。

---

## 1. 两层诊断

| 层次 | 观察对象 | 重点问题 |
|---|---|---|
| Agent 诊断 | 计划、消息、上下文、工具调用、实验产物、验证依赖 | 哪一步偏差、关键条件是否进上下文、错误如何传播 |
| LLM 诊断（仅 level=agent+llm） | 执行模型关键步骤的隐藏状态、信息可读出性、选择性激活 | 模型如何表示/使用条件、内部变化对错误是否有可重复影响 |

**能力 vs 机制的边界（P0）**：一次失败不能证明模型「绝对不会」；探针读不出某信息 ≠ 该信息不存在于模型内部。诊断结论一律按「在给定信息下该步推断是否成立」下判断，不用事后信息反推当时必然错误。

---

## 2. 失败条件分类

诊断输出必须落到结构化失败条件：

| 失败条件 | 判定依据 |
|---|---|
| 信息缺失 | 关键条件未进入上下文（可核对轨迹） |
| 条件错误合并 | 同对象不同条件的结论被当成同一结论（查论断图 scope） |
| 验证共用错误依赖 | 两个"独立"结果共用同一错误前提（查 source 链） |
| 无依据确认 | 断言缺少 support 边或来源 |
| 修复失效 | 修好后下游仍错 / 改错正确内容 |

## 3. 工作流

### Phase 0：定位断言

把待诊断内容拆成逐个论断，标注每个论断的证据链（追溯到论断图 `claim_id` 或实验 run 号）。

### Phase 1：证据资格裁决（规则层，非图连通）

对每条依据执行 Stored-Is-Not-Supported 式裁决：
- 来源角色：`实验观测/文献转述/假设/推论`——假设与推论**不得**充当已证事实；
- 有效期：依据是否过期/被后续证据推翻；
- 依赖：是否共用同一可疑前件（→ 共同依赖失败）。

### Phase 2：快速定位管线（L1–L6）

输入：`trajectory_path`（执行轨迹）或待诊断文本中的推理步骤序列。

**L1 轨迹分层重组**（DiLLS 三层，manifest 先验）：把轨迹重组为 `plan`（计划级：skill 派发、失败、重规划）→ `step`（步级：单 skill 的操作序列 + 状态 + 责任 agent）→ `log`（原始证据）。**分层以 manifest `pipelines` 为先验直接落位**，不需要 NL probing 去推断计划结构；仅当轨迹缺层（无 progress 记录的裸日志）才降级用 probing 式归纳补齐，并标注「结构为推断」。

**L2 依赖图构建**（DeFA：协议 ∪ 语义）：
- 协议依赖（确定性）：skill 派发→产物、工具调用→结果、上游 provides→下游 consumes；
- 语义依赖（LLM 归纳）：后续步骤使用了先前的结论/数值/状态；
- **论断图特化**：步骤引用同一 `claim_id` 或 `source` → 语义耦合边——把「共同依赖」检查变成图查询，语义归纳只补论断图覆盖不到的缺口。

产物 `<target>-deps.json`（节点 = step，边带 `protocol/semantic/claim` 类型）。

**L3 候选召回**（DeFA 分段视图 Vj）：长轨迹按 plan 边界分段；对每段构造 Vj =（其余段摘要 + 本段全文 + 其余段摘要）逐段召回候选嫌疑步。**召回不裁决**——每个候选必须带理由 + 失败条件类别，禁止在召回阶段收敛到单一假设（SAGE 多假设纪律）。

**L4 失败传播分析**（DeFA Gf + DiLLS 补偿识别）：对每个候选沿依赖图标**上游来源**（错误从哪来）与**下游影响**（传到哪）；多个下游症状共享同一上游嫌疑 → 共同前件，优先级提升；某步失败但下游已补救 → 标记 `被补偿`，症状 ≠ 根因。

**L5 裁决决定性错误**（DeFA 反事实判据 + DiLLS 失败分级）：decisive error = 最早的「若纠正即整体成功」的错误步。输出四类分级：

| 分级 | 含义 | 是否干预点 |
|---|---|---|
| 决定性错误 | 纠正它整体即成功 | ✅ 进 Phase 3 |
| 传播后果 | 由上游决定性错误波及 | ❌ 随根因修复 |
| 被补偿失败 | 曾失败但下游已补救 | ❌ 记录即可 |
| 计划性冗余 | 不该执行却执行了的步骤 | ✅（I2 计划级干预） |

每个决定性错误绑定：责任 skill/agent + 失败条件类别 + 证据 span。

**L6 验证依赖核验**：对决定性错误的验证链执行规则层三查（Phase 1 的来源角色/有效期/共同依赖，针对其依赖闭包复查）。

### Phase 3：分级干预菜单（I1–I3，DoVer + AGDebugger）

按 `../_shared/intervention-protocol.md` 生成干预菜单：每个决定性错误给出 I1 指令级 / I2 计划级 / I3 配置级候选（由轻到重，失败条件→干预映射见共享协议 §2），每项标注「重跑后应观察到什么」（验证条件）。

- **多个干预可能都修好同一失败，修好 ≠ 找到唯一根因**（P0）。
- 菜单经 **H2 审批**后交 `research-autopilot` 执行干预重跑；判定四类（Validated / Partially Validated / Refuted / **Inconclusive**——agent 未遵循干预必须单列，不得计入成败）。
- `Validated` 干预自动进入 `rsi-evolver` 蒸馏输入（验证过的干预 → 可复用策略）。

### Phase 4：诊断报告

## 4. 诊断报告（固定模板）

```markdown
## 诊断报告（diagnosis）
| 条目 | 判断 | 置信度 | 失败条件 | 依据 | 未决项 |
|---|---|---|---|---|---|
| <论断1> | 成立/存疑/错误 | 高/中/低 | <第2节分类> | <claim_id / run 号 / span> | <真值未知部分> |

## 决定性错误（L5 裁决）
| 嫌疑步 | 责任 agent/skill | 分级 | 失败条件 | 上游来源 | 下游影响 | 干预候选 |
|---|---|---|---|---|---|---|
```

**P0**：`依据` 必须可追溯（claim_id / run / span），`未决项` 必须显式，无依据不下强制正误标签。

---

## 6. Gate Check

- 诊断报告含 `判断/置信度/失败条件/依据/未决` 五列
- 证据资格经规则层裁决（来源角色/有效期/依赖）
- 快速定位管线 L1–L6 完整：依赖图、失败传播分析、四类分级（决定性/传播/被补偿/计划性冗余）齐备
- 干预菜单分级（I1–I3）且每项带验证条件与预期观察
- 无「图连通即支持」的越界结论
