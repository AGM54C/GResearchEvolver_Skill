# 干预协议 v2

1. 定位观测失败与候选原因，记录事件/产物/论断 ID，不把最早坏边当潜在根因。
2. 等待阶段暂停；保存工作区 checkpoint、命令、输入、预算和外部状态说明。
3. fork 未修改对照与有修改分支；明确改动的配置/指令/数据、科学里程碑和成功标准。保存稳定 milestone_id；目标改变时使用新 ID，不强行对齐冲突目标。
4. 实际运行，检查干预遵循度和外部状态可比性。种子相同只是匹配因素之一。
5. 重复对照；`tool intervention` 按声明的独立分析单位给四类判定。两侧 measurement_contracts 必须列明相同的 estimand/metric/unit/analysis_unit/evaluation_data_hash。改估计量或评价总体不能当作干预改进；缺少可比性、样本不足、不遵循或环境变化均为 Inconclusive。程序检查的是声明的一致性，不能证明声明真实；几次成功不证明唯一根因。
6. 人工可批注、修正语义对齐或拒绝建议；记录理由。验证有效的策略仍需 RSI 独立 audit 才能成为默认策略。

Progress 是达成的科学里程碑比例，不是完成 skill 数。恢复限于文件；远程状态和不可逆外部动作不能自动恢复。
