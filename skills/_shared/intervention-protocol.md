# 分级干预协议（Intervention Protocol，共享定义）

> 被 `diagnosis-clinician`（生成干预菜单）、`research-autopilot`（执行干预重跑）、`rsi-evolver`（蒸馏 Validated 干预）共同引用。
> 目标：把「人为介入」从抽象审批变成**可分级、可验证、可沉淀**的反事实干预（AGDebugger 调试循环：识别错误 ↔ 实验修正互相强化；DoVer do-then-verify：假设正确性由干预结果检验，不由措辞精确性检验）。

---

## 1. 干预三级类型学（I1–I3）

| 级别 | 干预对象 | 典型操作 | 来源 |
|---|---|---|---|
| **I1 指令级** | 给子 skill / 子 agent 的指令文本 | a) **加具体化**：计划粒度过粗 → 拆成可直接执行的动作；b) **简化拆分**：复合指令 → 先验证最小子任务；c) **补关键条件**：把任务允许的关键信息显式写入指令 | AGDebugger 三类编辑（Add 14/24 最常见，对应计划粒度失败模式）+ DoVer 补任务允许信息 |
| **I2 计划级** | pipeline 步骤序列 | 重排步骤 / 分解步骤 / 替换步骤（如换验证方法） | DoVer 更新计划 |
| **I3 配置级** | skill / 工具 / 参数选择 | 换子 skill / 换工具 / 换参数 / 换执行模型 | AGDebugger 设计目标 G4 |

**干预生成引导（两问，AGDebugger）**：对每个决定性错误至少考虑两个反事实——
1. 「同输入重跑会怎样」→ 随机性排查，属 E6 幂等重跑，**不算干预**；
2. 「换了消息 / 计划 / 配置会怎样」→ 真干预，按 **I1 → I2 → I3 由轻到重**排序，轻者优先。

---

## 2. 失败条件 → 首选干预映射

| 失败条件（diagnosis-clinician §2） | 首选干预 | 说明 |
|---|---|---|
| 信息缺失 | I1c 补关键条件 | 关键条件显式进入指令上下文 |
| 条件错误合并 | I1a 加具体化 + 修断言 scope | 指令中显式区分同对象不同条件 |
| 验证共用错误依赖 | I2 替换步骤 | 换独立验证源，切断共同前件 |
| 无依据确认 | I1a 加具体化（要求溯源） | 指令强制 claim_id / run 回接 |
| 修复失效 | I2 计划级 | 单点修补不够，重新审视步骤组织 |

## 3. 执行与 checkpoint 纪律

- **H2 审批（P0）**：干预菜单（级别 / 操作 / 验证条件 / 预期观察）呈给用户批准后才能执行，禁止擅自重跑。
- **good-enough checkpoint**（AGDebugger）：干预重跑**不要求完美恢复外部世界状态**；以 `progress.json` 已完成阶段为恢复点，只重执行干预点及其受影响的下游阶段；恢复到「接近」状态后由 agent 自行重估继续。
- **fork 语义，不覆盖**：干预重跑产生新 session 记录，**原轨迹完整保留**供前后对比（对应 AGDebugger 的 session 分叉可视化）。

---

## 4. 干预判定（四类，DoVer）

对每个已执行干预，按其验证条件判定：

| 判定 | 标准 |
|---|---|
| `Validated` | 重复干预 ≥2/3 次达成验证条件 |
| `Partially Validated` | 未完全达成但 Progress Made > 0 |
| `Refuted` | 重跑后失败条件复现且无进步 |
| `Inconclusive` | **agent 未遵循干预指令**——单列！不得计入成功也不得计入失败 |

**Progress Made 量化**：`PM = (A(τ̃) − A(τ)) / K`。里程碑数 K 取 manifest `pipelines` 阶段数；A(τ) = 干预前已完成里程碑数；A(τ̃) = 干预后。
**回溯性干预备选尺度**（2026-10-19 验证轮发现）：对已完成 pipeline 的回溯性干预重放，里程碑尺度分母失义（A(τ̃)−A(τ)≡0）→ 改用**缺陷单元尺度**：K = 干预覆盖的缺陷单元数（重复条目 / 散落文件 / 无效重试序列等），A(τ̃) = 重放验证到的修复单元数；PM 须注明「回溯重放有效性，非现场改进增量」。

**纪律（P0）**：
- **修好 ≠ 唯一根因**——多个干预可能修好同一失败，判定只说明「该干预在该条件下有效」，禁止写成「找到了根因」。
- **Inconclusive 必须单列**——DoVer 教训：agent 未遵循干预时，把结果记到干预头上会污染归因。

---

## 5. 蒸馏接口（→ rsi-evolver）

判定为 `Validated` 的干预自动成为 `rsi-evolver` `distill` 的输入源：

- 经验 `failure_mode` ← 诊断的失败条件类别；
- 经验 `为什么` ← L4 失败传播分析（上游来源 + 下游影响）；
- 经验 `如何应用` ← 干预操作本身（级别 + 具体改法）。

**验证过的干预 → 可复用策略**：DoVer / AGDebugger 均止步于人工修复；我们把 Validated 干预接入 RSI 蒸馏闭环，让每次验证过的修复自动沉淀为 M3 策略——这是本 skill 集合与文献系统的核心差异。
