# 科研视觉工作：人类监督与受控进化

本协议适用于 figure-mimic 和 slides-builder。研究者负责科学方向、价值判断与表达取舍；AI 负责提出可比较方案、执行、发现缺陷和报告证据。AI 的审美评价不能替代科研 taste，也不能自行改变研究问题或升级证据强度。

## 介入点和报告

科研视觉工作默认使用 checkpoints；沿用用户已选的更细 every-stage 模式。研究者已明确的具体选择应记录并沿用，无需对每个绘图命令重复确认；科学方向变更和版本采用仍需真实研究者决定，不以自动分数或超时当作同意。关键节点为：

1. **brief/storyboard**：目标读者、科学问题、需要强调/保留的限定、推荐编码或叙事、备选和成本。先形成可审阅方案；已有明确决定无需重复确认。
2. **preview**：实际图像/逐页渲染、改动前后差异、科学与视觉缺陷、局部修正理由。人的修订可以针对图、页、节点、边或具体论断。
3. **delivery**：来源、脚本、环境、文件检查、人工意见落实情况、仍未完成的检查。审阅当前产物版本之后再标记为采用。

受管运行每阶段生成版本化 report.md/report.json。具体命令、反馈与分支见 [共享人机协议](human-guided-research.md)。普通渲染命令仅生成草稿，不能自己执行 approve。直接运行工具生成的 report.md 也始终标为 human_review:pending；它不代替 runtime 的门控回执。

反馈至少说清对象、问题、理由和期望。例如：“第 4 页把观察性关联写成机制，请改标题并保留混杂解释”，比“这页不好”更可执行。对科学判断、表达偏好和文件故障分别保留原意见，不把偏好当成普遍真理。

`stage-memory` 可将报告、解释和反馈投影为 nodes/edges。把图/页/假设版本与源数据、代码、预览、评审相连；`derived_from`、`revises`、`responds_to` 只表达已记录关系，`supports`/`contradicts` 需要相应语义裁决。

## RSI：允许提案，采用由人监督

两个目标均已注册：`skill:figure-mimic`、`skill:slides-builder`。宿主按以下流程实施改进；运行时不会凭空产生候选或持续调用模型。

1. 从真实报告/反馈提取失败类别、影响与证据。科学方向或叙事目标有分歧时先提交给研究者，不能把分歧偷偷改成优化目标。
2. 提出具体、有限的改动：例如中文字体选择、置信区间保留、模板文字替换、溢出检测、讲稿解释或布局策略。保留基线；不同时更换内容、模型和布局后把收益归给其中一项。
3. 用 capability-freeze 固定任务、评分器、模型/渲染器版本、输入、预算、科学保护检查、主指标、失败定义、审核者与试验次数。不同领域、语言、长标题、缺失数据、负结果和模板应有未参与调优的验收材料。
4. 宿主生成候选包，以真实 report_id/feedback_id 调用 capability-propose，再实际 evaluate。候选包不能修改受信任评分器、人工批准或科学方向契约。
5. 评估结果交研究者，解释收益、不确定性、回归与成本。通过 audit 仍需 capability-review 和 capability-activate；拒绝和停止都有效，不反复更名候选规避决定。后续新运行显式绑定版本，旧运行不变，可整包回滚。

### 评估分层

| 层面 | 可测对象 | 不能据此声称 |
|---|---|---|
| 科学保真 | 已知数据/区间/单位的保留、源引用、限定语与图关系的专业复核 | 引用哈希匹配证明结论正确 |
| 文件与恢复 | 可打开、可重建、缺字/越界故障、模板未改部件、失败回执与版本保留 | 文件通过代表图有科学价值 |
| 表达与理解 | 研究者理解题、读图准确率、误读类型、盲评和分歧 | AI 自评分或点击接受代表理解提升 |
| 偏好与投入 | 风格偏好、修改时间、认知负担、运行成本 | 单人的偏好普遍适用于所有领域 |

对候选先检查科学保护条件，再比较声明的指标；不把几项任意加权成“科研 taste 总分”。有争议或未知项保持待定。自动修复有预算和停止条件，不能通过降低检查门槛或隐藏失败来宣称进化成功。

本地 reviewer 名称是可信操作流程中的身份标签，不是独立身份认证。不能靠字符串名称防止同权限恶意进程冒充人；需要对抗隔离时，沿用外部可信评估/签名权限域和受保护的人工控制面。当前工具没有新增自主改变研究方向或无人监管晋升的能力。

## 工具与复现

```text
python -m pip install -r skills/_shared/visual-requirements.txt
python skills/_shared/examples/visual_research.py --output visual-demo
python skills/_shared/runtime/research.py --store visual-demo/state serve
```

示例使用明确标识的合成数据，默认停在 brief 审阅，后续依次生成数据图、示意图和 PPT。它演示执行与介入，不是科研能力或用户研究结果。脚本失败时读原始错误，修订后用新输出目录；managed 分支保留原报告和源文件。

可复现表示记录并验证输入、代码、配置和环境，能重建相应内容；不同字体、渲染器或文件时间戳可能产生不同字节，不能默认 PNG/PDF/PPTX 跨环境完全一致。生成工具不联网、不下载模型、不修改 Office 全局设置。
